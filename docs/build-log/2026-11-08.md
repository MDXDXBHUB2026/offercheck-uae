- **What the test does:** it calls `runWithAudit` on 63 offers, one after another (2 fixtures, 43 dev cases and 18 holdout 1 cases). The longest of the 61 eval offers is 208 characters. Each call runs the rules and builds an audit chain, with one SHA-256 per entry through `crypto.subtle`. The test then checks every entry's keys and string values.
- **Measured** with the vitest JSON reporter. The test and the timeout were not changed.
  - `npx vitest run src/lib/audit.test.ts`, 10 runs: 111, 67, 59, 69, 56, 58, 56, 101, 77 and 89 ms. Each run passed 104 of 104 tests.
  - `npx vitest run`, 3 runs: 625, 442 and 523 ms. Each run passed 779 of 779 tests.

One possibility is that the worker was stalled by other load on the machine during that run, but this was not checked or reproduced. The stress check fits that idea: a parallel build made the test up to about 4.6 times slower than the slowest unloaded full run (2,886 ms against 625 ms). It still stayed under 5,000 ms, so the cause is not confirmed.
- **Still open:** FLK-1. It did not reproduce in these 16 runs, 3 of them under build load.

## Batch A rules: the Batch A commit (see git log)

Owner-approved design, with the owner's changes. Tests were written first. Before the change, 25 of the new rule tests failed (every new positive and the case 2 and 3 negation tests), the 3 offer-notice UI tests failed, and `offerLikeness.test.ts` could not load. One first-draft case 1 negation test failed for an unrelated reason (negation does not carry across "and") and was replaced by two that pin current behaviour.

- **GAP-1 (RF-001).** An employer named at the start of a list (`covers`, `pays`, `pays for`, `bears`; not `sponsors`) now covers an item the employer usually pays (visa, work permit, residence, Emirates ID, medical, insurance, ticket, flight, airfare, accommodation, housing, relocation, uniform, transport). A fee noun in that item (processing, registration, admin, application, security, deposit, training, clearance, agency, service, handling, documentation, verification, courier) always fires. A candidate marker or ask before or after the cost in the same sentence ends the cover. `The company sponsors your visa and processing charges AED 2,500` stays High. The look-back is limited to 160 characters, so it stays fast on long text.
- **H21 (RF-002).** `we send` or `you will receive` right after "code", "pin", "otp", "passcode" or "password" no longer clears the part, and a new pattern flags "share, send, forward, give, tell, WhatsApp, email or reply with" a code that we send or you receive. "Enter the code" stays unflagged on purpose.
- **GAP-7 (RF-002).** A photo, scan, copy or screenshot of a bank, debit, credit or ATM card, a Mastercard or a Visa card fires. A photo of "your card" fires only with front and back, CVV, expiry or PIN within 60 characters. "Visa" alone stays excluded.
- **Band design: decided, no threshold change.** The UX-1 amber chip covers a Low score with a finding.
- **Offer notice (GAP-8).** `src/lib/offerLikeness.ts`: four signal groups, recorded at check time like the language notice. The notice shows only when the band is Low, no group matches and the tier 1 language notice is not shown. It is not imported by the rules, the scoring, Intake or the server (test). It is **not recorded in the audit trail**: the run's entries are written on the server, which must not import it, and the browser only adds gate-decision entries. A new field would not change the hash-chain format, but it would need one of those two, so it was left out.
- **Eval.** On the 77 cases, only H21 changed: 0, Low to 60, High, RF-002. Holdout 2's blind result stays 15 of 16, with a separate note that H21 passes after tuning. The dev precision and recall are unchanged.
- **Public copy.** Items 1, 2, 4 and 5 in `publicLimitations.ts` and the matching doc bullets were rewritten. The parity, ASCII and banned-term tests pass.
