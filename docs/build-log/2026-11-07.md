## Step 4: visual design

Spec: `docs/step4-design.md`. The repo has no mockup image or file, so the spec text was the only source. Nothing under `src/lib` changed; `redFlag.ts` sha256 is still `789dc2b29a30940951257c677bddcb4eaf995bb8a187a19e3583ca51d1ebb76f`.

### What changed
- Fonts: Inter (body) and Space Grotesk (headings) through `next/font/google`, self-hosted at build time. In the browser, every request went to `localhost`; no request went to Google.
- Colours: the spec palette, light only. The old dark-mode block was removed, because the spec gives no dark palette.
- Score: a semicircle gauge (decorative, `aria-hidden`), the score and band as text, and an arithmetic line built only from the returned findings (`src/components/scoreArithmetic.ts`). The line is shown only if its result equals the server's score; otherwise it is left out.
- Evidence cards: quote, severity chip with points, rule ID, coloured left border plus the severity word in text.
- Warning mentions: dashed, untinted, labelled "Mentioned in a warning, not counted in the score".
- Agent run: icon, name, summary, measured `durationMs`, or "Not run" and "Not implemented yet".
- Sample buttons: "Fee scam", "Clean offer", "Injection attempt" (the synthetic fixtures `SCAM_OFFER`, `LEGIT_OFFER` and eval offer A01).
- "What this check cannot do" panel, read on the server from `docs/known-limitations.md`.
- `package.json`: `"engines": {"node": ">=24 <25"}`, matching `.nvmrc` (24.19.0).

### Left out from the spec
- **Matched-phrase highlight inside the quote.** Findings carry the whole clause as evidence, not the matched span. Finding the span in the browser would need the rule patterns there, which must stay out of the client bundle. Changing the finding shape would change `src/lib`.
- **The word "capped" in the spec's example "40 + 20 + 20 + 20 = 100, capped".** The app writes "capped at 100" only when the sum is over 100, so that example shows as "40 + 20 + 20 + 20 = 100".
- **Any number the app does not compute.** The only times shown are the measured `durationMs` values (a test checks this).
